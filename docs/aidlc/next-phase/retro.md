# Retro: next-phase

> 复盘日期：2026-10-15　参与：人类 + 编排者 + 各角色（pm/architect/qa/dev/tea ×4 轮互审 + verifier ×3 轮终检）

## 什么有效

- **TDD 锁 + 人类解锁纪律**：pk5 夹具缺陷由 dev 按纪律上报（而非改断言凑数），字节级证据经编排者复核后走人类裁决（"选择A方案"）——确定性实现无法同时满足两个矛盾断言时，正确答案是修夹具不是修实现。场景 18 同法处理（"2个任务都请在真实环境重新核验"解锁打包）。
- **verifier 新鲜上下文终检**：三轮终检两轮抓到编排者自审盲区（B1 计数漂移、M7 未落盘、2 处注记失准）——独立第二双眼睛的价值经实证。
- **真实环境人类环核验**：用户两次要求"真实环境重新核验"，逼出了 A1 表单真实作答、T04 真实拒绝零残留等机器模拟给不出的证据；用户明确拒绝"追认机器模拟结果"。
- **机械校验（F4）兜底对齐拍**：编号集合比对把"对齐拍"从 prompt 纪律升级为机制强制（缺口/幻影 deny）；表边界收口后第二张表不再能注入假证据。
- **fail-closed 设计方向**：宁可少算交人工（缺口误报）不可多算成假覆盖——所有修订方向一致，无一处引入静默放行。

## 什么没用

- **文档绝对计数反复发作**：15→17→18 场景、115→116 检查的连锁同步全靠人肉，三次评审两次抓到计数漂移，其中一次是 R1 自己的提交把刚修好的 B1 又弄失效。计数表述应去绝对化。
- **留痕纪律两处失守**：一次解锁裁决漏录 decisions.md（审计断链，被四方评审同指）；一次演示只"recorded in session"未落盘（M7）。 orchestrator 用 shell 追加 decisions.md 绕过了自家守卫的 Write 前缀校验——语义上 append-only 无害，机制上不应成为惯例。
- **表单呈报未作答的等待成本**：gate2 审批两次呈报未作答，期间走了两轮"呈报→记录→等待"；门控铁律下这是正确保守路径，但提示表单呈现时机应尽量贴近人类在线窗口。

## 学到的东西

- 三方以上独立同指是 MAJOR 定级的强信号（本轮 3 项 MAJOR 均四方同指）。
- 门控表单的批准措辞（如"批准"对应推荐项）应逐字记录并显式声明解释，避免歧义。
- TDD 锁锁定期间，任何"顺手修"都要先问：是否锁定文件？——场景 18 的头注释和断言加固因此多等了一轮解锁裁决。
