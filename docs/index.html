01这是什么

AI-DLC 是 AWS 提出的 AI 驱动开发方法论：AI 负责计划、提问、产出；人类负责回答、决策、审批。本插件把这套方法论变成 ZCode 里的可执行流水线——不是又一个小工具，而是把「门控」「工件链」「角色分工」变成机制。

Inception 需求→ Gate#1 设计门（人审）→ Construction 实现→ Gate#2 交付门（人审）→ Operations 运维→ done

三层设计（一个核心，多种来源）

层来源本插件的落地
方法论AWS AI-DLC三阶段双门控、Bolts/Units、四拍仪式（提问→工件→评审→门控）
实施模式BMAD Method（AWS 中国博客实证）角色化 agent、约束前置、并行产出、Party Mode 交叉互审
工程实践Anthropic《AI-native SDLC playbook》工件链即审计链、hooks 作确定性门、verifier 新鲜上下文终检
核心哲学
  • 每个阶段固定四拍：提问 → 工件 → 评审 → 门控，不可跳步
  • 门控分两层：AI 互审抓硬伤（快），人类审批判语义（慢）——你的注意力只花在门上
  • 自主权从不推断：一次「按推荐走」只对当前阶段有效
  • 每份工件一次 git 提交——提交链即审计链，任何一步可回溯

02特性

全部机制经过真实项目端到端验证（含配额熔断降级、并发写、对抗绕过等压力场景）。

🎭十个角色子代理

六个生产角色（pm / architect / dev / qa / tea / verifier，约束前置）+ 四个只读互审角色（reviewer-pm / -architect / -qa / -dev，无 Edit/Write 工具——互审只读是机制保证，不靠提示词）。

🛡️机制化守卫（非口头承诺）

5 个 hooks：未过门禁写实现计划会被 deny；TDD 锁下改锁定测试会被拦；门控置 approved 必须有人类回执且打回后旧回执作废；审计文件禁 Edit（防篡改历史）；损坏 state.json 时 fail-closed；.env/密钥路径写入被拒。

📜工件链审计

PRD、架构、测试策略、计划、评审、决策、复盘全部落 docs/aidlc/<意图>/，一工件一提交；人类反馈逐字进 decisions.md。

🔁断点续跑

state.json 记录阶段机与单元进度；中断后 /aidlc:resume 自动四方对账（state/磁盘/git/决策），按 unit 粒度恢复，不重跑已完成的。

🔍新鲜上下文终检

Gate#2 派独立 verifier：自己跑测试、双查计划外文件、抽查验收、核实前轮评审声称——实战中真的抓到过编排者的盲区。

🧯配额降级协议

角色代理因配额/网络不可用时：先查工作区再重派 → 内联代跑留痕 → 门审时打包追认 → 恢复后补独立复核。降级不弃纪律。

03安装

本仓库本身就是一个 ZCode marketplace，两种来源任选其一。

前置要求：Node.js ≥ 16

hooks 通过 PATH 上的 node 运行。机器上没有 node 时 hook 会报错——而 hook 报错 = 守卫静默失效（fail-open）。装完可用 node --version 验证。

方式一：从 GitHub 安装

# 本仓库为私有仓库，目标机器需已登录 GitHub
zcode plugins marketplace add https://github.com/Tintac-CN/aidlc-zcode
zcode plugins install aidlc@aidlc-zcode

方式二：从本地目录安装（内网/免认证）

git clone https://github.com/Tintac-CN/aidlc-zcode.git
zcode plugins marketplace add /path/to/aidlc-zcode
zcode plugins install aidlc@aidlc-zcode

或在客户端 Plugin Marketplace → + → Add Plugin Marketplace 粘贴仓库地址，然后在 Discover 里找到 AIDLC 点 Get。

⚠️ 装完必须重启 ZCode

命令、角色 agent、hooks 都在启动时注册。不重启的话，旧会话看不到新组件（实测教训）。

验证安装

zcode plugins list | grep -A2 aidlc
# 期望输出：skills: 2, commands: 10, hooks: 5

zcode commands list        # 应看到 10 个 /aidlc:* 命令
zcode skills list          # 应看到 aidlc 与 party-review

hooks 自动启用，无需任何配置。输入框打 / 能看到 /aidlc:inception 等命令即装好了。

04快速开始（3 分钟）

插件没有「启动」按钮——它常驻 ZCode，在任意项目里用斜杠命令驱动。

1

打开一个 git 项目

工件链靠 git 提交做审计。项目还不是 git 仓库？插件会提醒你 git init。

2

一句话意图启动

/aidlc:inception 给这个工具加一个导出CSV的功能

插件会建 docs/aidlc/<意图名>/，并行调度 pm / architect / qa 产出 PRD、架构、测试策略三份工件。

3

过第一道门

/aidlc:gate

AI 交叉评审三份工件（抓硬性不一致），然后停下来等你：表单化审批（通过 / 打回+反馈）。你的反馈逐字进 decisions.md。

05完整教程：一次真实交付的全生命周期

以下流程来自一次真实运行：从「给命令行待办工具加导出 CSV」一句话，到 72/72 测试全绿、双门批准、28 个审计提交的完整交付。照着走一遍，你就掌握全部用法。

第 1 步 · Inception —— 把一句话变成三份工件

/aidlc:inception 给一个命令行待办事项工具加导出CSV功能
  • 编排者先建目录与骨架（intent.md + state.json + decisions.md），再并行扇出三个角色
  • 意图有歧义会先问你（最多 3 个关键问题）——AI 不猜，你的裁决逐字留痕
  • 三工件齐后跑「对齐拍」：交叉核对验收标准编号与语义对齐表，错位派回对应角色回填

产出：prd.md（用户故事+可测验收标准）、architecture.md（架构+数据模型+决策理由）、test-strategy.md（P0/P1/P2 风险排序）。

第 2 步 · Gate#1 设计门 —— AI 互审 + 你拍板

/aidlc:gate
  • Party Mode 交叉互审：reviewer-pm / -architect / -qa / -dev 四个只读视角并行评审，产出 reviews/gate1-ai.md（BLOCKER/MAJOR/MINOR 分级，每条带文件级证据）
  • 互审结论汇总呈给你，AskUserQuestion 表单：批准 / 打回+反馈
  • 批准顺序被 hook 强制：先写 decisions.md 回执 GATE-APPROVED gate1 <日期>，再推进 state——颠倒会被 deny
  • 打回则回 Inception 修订：只重跑被点名的角色，复审重点核对上轮 BLOCKER 是否消解
实战数据

真实运行中，Gate#1 互审抓出 3 个 BLOCKER / 9 个 MAJOR——包括一个「按字面实现会静默删数据」的 Windows 原子写缺陷。这就是互审的价值。

第 3 步 · Construction —— TDD 与并行泳道

/aidlc:construct
/aidlc:lock-tests        # 失败测试提交后上锁
# ……dev 实现至全绿……
/aidlc:unlock-tests 契约字段写错了   # 仅当契约本身有错，经你批准解锁
  • Sprint Planning：PRD 拆成 units（plan.md + units/*.md）
  • TDD 铁律：先写失败测试并提交 → /aidlc:lock-tests 上锁 → 此后改测试文件会被 hook deny；契约有错走 unlock（理由进 decisions.md）
  • 并行泳道：dev（TDD 实现）｜architect（基础设施）｜tea（E2E/性能，量化阈值）
  • 每完成一个 unit 更新 state.json 的 unitStatus 并提交——中断后 resume 只续未完成的

第 4 步 · Gate#2 交付门 —— 独立终检 + 你验收

/aidlc:gate
  • 互审 + 独立 verifier（新鲜上下文）：对照 plan 逐单元核对、自己跑全量测试、双查计划外文件（git status + git ls-files）、子进程抽查验收
  • verifier 只报告不修复——发现的问题交回对应角色
  • 你审批（表单）→ 回执 GATE-APPROVED gate2 → 进入 Operations

第 5 步 · Operations 与完结

/aidlc:ops
  • 产出 ops-runbook.md（运维手册：测试/备份/退出码语义/已知边界）
  • SLA/阈值/部署窗口由你决定，裁决逐字留痕
  • 复盘 retro.md（什么有效/什么没用/下个改什么）→ phase=done，生命周期闭环

中断了怎么办

/aidlc:resume          # 四方对账：state vs 磁盘 vs git log vs decisions
/aidlc:status          # 随时查当前阶段/门控/工件/下一步

新开会话时插件自动注入当前 intent 的状态摘要与最近的决策记录——续跑不靠记忆，一切以落盘状态为准。

06命令参考

命令作用备注
/aidlc:inception <意图>启动意图：建骨架 → 并行产出 PRD/架构/测试策略歧义先问，最多 3 问
/aidlc:gate [gate1|gate2]执行当前门：AI 互审 → 人类审批推断真值表覆盖全部相位；打回自动回退
/aidlc:construct拆 units、TDD 锁、并行实现前置：gate1 approved（hook 强制）
/aidlc:ops运维手册 + 参数收集 + 复盘完结前置：gate2 approved
/aidlc:status查阶段/门控/工件清单/下一步含 git 提交状态对账
/aidlc:resume [slug]断点续跑（四方对账 + unit 粒度恢复）SessionStart 自动预热
/aidlc:lock-testsTDD 锁置位（校验测试已提交）此后改测试被 deny
/aidlc:unlock-tests <理由>经人类批准解锁（理由逐字留痕）修完契约重新上锁
/aidlc:archive <理由>终止 intent（archived，历史保留作审计）打回 3 轮不收敛 / 需求取消时
/aidlc:eval插件自检回归（hook 语法 + 守卫 28 场景）改插件配置后必跑；CI 也会自动跑

07工作原理

状态机与工件

docs/aidlc/<slug>/
├── state.json          # 阶段机：phase / gates / tddLock / unitStatus / history（只追加）
├── intent.md           # 一句话意图（用户原话逐字保留）
├── prd.md  architecture.md  test-strategy.md     # Inception 产出
├── plan.md  units/     # Construction 计划
├── reviews/            # 各门 AI 互审与 verifier 报告
├── decisions.md        # 人类决策台账（只追加；门控回执在此校验）
├── audit.log           # Stop hook 逐轮审计
└── ops-runbook.md  retro.md                      # Operations 产出

五个守卫 hooks（插件自带，自动启用）

Hook事件强制内容
guard-gatesPreToolUse未过 gate1 禁写 plan/units；TDD 锁禁改锁定测试（tddLockPaths 限定范围）；门控置 approved 须有人类回执（打回后旧回执作废）；state.json/decisions.md 禁 Edit、只追加、乐观锁；损坏 state.json fail-closed
guard-pathsPreToolUse.env/密钥/凭据文件写入 deny（.env.example 白名单）
guard-testsPostToolUseTDD 锁期间测试文件被改 → 警告注入（提示走解锁流程）
session-contextSessionStart新会话注入活跃 intent 状态 + decisions.md 最近 15 行
audit-logStop逐轮摘要追加 audit.log
🔒 诚实的边界声明（重要）
  • hooks 是流程约束（防手滑、强制仪式），不是安全边界——Bash 重定向等间接写可绕过；强边界请放 CI / 分支保护层
  • 角色「常驻约束」是提示词，长上下文/对抗输入下可能被稀释——门控处的人类复核是唯一可信兜底
  • hook 脚本出错会 fail-open（静默失去保护）——改插件后务必跑 /aidlc:eval
  • 多 intent 并行会话不在当前版本支持范围（活跃 intent 按 updatedAt 判定）

08FAQ

装好了但看不到命令？

重启 ZCode。命令/agent/hooks 都在启动时注册；更新插件后同样需要重启（并确认 plugin.json 与 marketplace.json 的版本号已 bump，否则 update 不生效）。

能在 headless / CI 里跑吗？

可以，但有边界：门控涉及人类审批，headless 下会停在审批处；多 agent 编排的长任务（inception/construct）在 headless 可能被超时截断——这类命令建议在交互会话跑，中断后 /aidlc:resume 对账续跑。

角色代理派发失败（配额/网络）怎么办？

插件内置配额降级协议（SKILL §8）：自动先查工作区（代理失败≠零产出）→ 重派一次 → 仍失败则编排者内联代跑并在 decisions.md 留痕，门审时打包请你追认；恢复后建议补一轮独立 verifier。

它会把我的代码改成什么样？

所有工件只落在 docs/aidlc/ 下；代码改动只发生在 Construction 且被 TDD 锁与门控约束。decisions.md / state.json 的 history 是只追加的（hook 强制），人类决策记录不可被 AI 删改。

和直接用大模型写代码有什么区别？

没有门控的 AI 编码是「信任我」；AIDLC 是「验证我」——每阶段有工件、有互审、有你的一票，且你的每次裁决都有回执和审计。真实运行里，互审和独立终检都抓到过人审前的问题。
